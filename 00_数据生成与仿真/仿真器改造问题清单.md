## 0. 背景：仿真器现在能做什么，缺什么

**当前能力（v0.1）**：按《采集侧确认清单》的数据契约生成合成三相电流，
支持 8 类故障注入，用于管线自检 / QA 基准 / ML 打底。

```
generate_dataset(fs, duration, f1, amplitude, harmonics, fsw, pwm_depth,
                 snr_db, adc_bits, full_scale, imbalance, load_profile, faults)
  → (signal[N,3], timestamps_ns, metadata)
```

**当前故障库（8 类）**：`stall` 堵转 / `load_step` 负载突变 / `rotor_sideband` MCSA 边带 /
`spike` 冲击脉冲 / `harmonic` 谐波畸变 / `unbalance` 三相不平衡 / `degradation` 缓变劣化 ⚠️（将升级为
**随机退化**，见 §3.5） / `arc` 电弧。

**主要短板（本次要改的 6 个方向）**：

| # | 方向 | 现状 | 痛点 |
|---|------|------|------|
| 1 | 场景化构建器 | 负载包络 + 故障两个列表手工拼时间线 | 生成训练/测试集费劲，无法批量、无法带标注 |
| 2 | 更真实 VFD 波形 | 恒定频率正弦 + 固定谐波 + 正弦 PWM 纹波 | 无启停加减速斜坡、无变转速、无真实 PWM 调制/死区 |
| 3 | 新增故障类型 | 8 类 | 轴承/定子匝间短路/偏心/齿轮箱/缺相等缺失 |
| 4 | 数据契约对齐 | metadata 部分契约字段 | 8 参数契约未完整落地，缺标定/满量程/CRC 等 |
| 5 | 流式/连续生成 | 一次性批量生成 (N,3) | 无法配合环形缓冲/看门狗/触发引擎做实时测试 |
| 6 | 混沌注入 | 无 | `08_鲁棒性` 4.2 列的 8 类混沌注入没有仿真支撑 |

> 红线：合成数据只用于**管线自检 / QA 基准 / ML 预训练**，最终验收仍以真实数据为准。
> 本次改造不改变这条红线，只让"合成数据"更接近真实、更好用。

## 1. 场景化构建器（方向 1）

### 现状
`load_profile=[(t0,t1,amp),...]` 与 `faults=[Fault(...),...]` 是两套独立列表，
调用方手工对时间轴。批量生成带标签训练集时容易错位、重复。

### 目标
提供一个**场景 DSL / 构建器**，用一句话描述一段工况，自动展开成时间线：
`启动 → 空载 → 满载 → 过载 → 停机 → 故障注入(带起止标签) → 恢复`，
并输出 ground-truth 事件表（供 ML 打标签 / 测试断言）。

### 需要电气工程师确认

- **SC-01** 目标设备最典型的**一个完整工作循环**是什么样？
  请给一条参考时间线，例如：`0-10s 启动(斜坡) → 10-30s 空载 → 30-60s 满载 →
  60-70s 过载 ×1.2 → 70-80s 满载 → 80-90s 停机`。（或提供真实工况录波曲线）
- **SC-02** 需要支持的**典型场景数量**？用于 ML 训练，希望批量随机生成多少条
  （如 100 / 1000 / 10000）？
- **SC-03** 场景是否需要**随机化参数**（每次生成时幅值/时长/故障严重度在区间内
  随机抖动，模拟样本多样性）？默认按 `±10%` 抖动可以吗？
- **SC-04** ground-truth 事件表输出格式偏好？默认提供
  `[(t_start, t_end, 状态/故障类型, 严重度, 置信参考), ...]` CSV / JSON 是否够用？
- **SC-05** 是否需要**串行多故障**场景（一个循环里多种故障先后出现，如
  M0 报告里 10-14s 边带 + 20-22s 堵转）？默认支持。

> 设计建议：新增 `Scenario` dataclass + `build_scenario()`，内部复用现有
> `generate_dataset`，保证向后兼容；事件表同时落盘 + 进 metadata。

## 2. 更真实 VFD 波形（方向 2）

### 现状
- 恒定基频 `f1=50Hz`，无加减速斜坡 → 无法验证"变转速鲁棒性"（TODO-E-P4 差异化的关键）。
- 谐波固定 {5,7,11,13}；PWM 用一条 `sin(fsw)` 正弦叠加模拟纹波，**不是**真实的
  SVPWM 调制，也没有死区效应。
- 无启动磁化涌流 / 冲击电流。

### 目标
支持**变频输出频率随时间变化**（斜坡启停、变速）、更接近真实的 PWM 调制与死区、
可选的启动涌流，让快路径状态机 / 慢路径 MCSA 在**变工况**下可验证。

### 需要电气工程师确认

- **VFD-01** 目标变频器的**型号 / 控制方式**？V/F、SVPWM、还是 DTC（直接转矩）？
  这决定波形模型选哪种（SVPWM 可解析建模，DTC 只能近似）。
- **VFD-02** 实际**输出频率范围**？如 `5 ~ 120 Hz`，额定输出 `50Hz`？（影响 f_min 下限，
  预处理带通 lowcut=5Hz 是否够）
- **VFD-03** 实际**载波/开关频率 fsw**？固定还是随负载变化？（当前默认 8000Hz）
- **VFD-04** **加减速斜坡时间**典型值？（如从 0 到 50Hz 用 5s 或 10s？）
- **VFD-05** 是否模拟**启动磁化涌流**（幅值 ×几、持续多久）？
- **VFD-06** 是否需要模拟 **PWM 调制边带**（载波频率 ± 基波，`fsw±f1`）？
  三菱 MCSA 诊断关注 `f1±2·s·f1`，PWM 边带可能干扰，需确认是否建模。
- **VFD-07** 是否需要**死区时间**效应（电压死区产生低次谐波/电流畸变）？给典型死区值（如 2~4 μs）或按默认 3μs。

> 设计建议：新增 `VFDProfile`（调制方式 / 频率曲线 / 载波 / 死区 / 涌流），
> `f1` 从常量升级为"频率轨迹" `f1(t)`；向后兼容保留 `f1` 标量入参。

## 3. 新增故障类型（方向 3）

### 现状
8 类：堵转 / 负载突变 / MCSA 转子边带 / 冲击 / 谐波 / 三相不平衡 / 缓变劣化 / 电弧。

### 目标
扩充故障库到覆盖**电机 + 传动 + 电气侧**常见故障，供 ML 分类打底。

### 需要电气工程师确认（请勾选最关心的，按"最想先做"排序）

- **FT-01 轴承故障**（滚动轴承外圈/内圈/滚动体/保持架）
  - 特征频率公式（BPFO/BPFI/BSF/FTF）需要给出轴承参数或默认一组。
  - 严重度分级（早期/中期/晚期，能量占比）？
- **FT-02 定子绕组匝间短路**
  - 表现：负序电流增大 / 特定谐波变化。给出特征，还是按默认负序电流建模？
- **FT-03 转子断条 / 断环**（与现有 `rotor_sideband` 的关系？是增强还是替代？）
- **FT-04 转子偏心（静态/动态）**：特征频率 `f1 ± k·fr`（fr=转频）？
- **FT-05 齿轮箱故障（点蚀/断齿）**：啮合频率 ± 边带，给齿数或按默认？
- **FT-06 缺相 / 单相断线**（鲁棒性 R6）：A/B/C 某相幅值掉到 ~0。
- **FT-07 电缆/接线松动**：间歇性断点 / 接触电阻发热导致的波形畸变？
- **FT-08 传感器故障**（不是电机故障，但和混沌注入重叠，确认归哪边）：
  偏置漂移 / 增益衰减 / 通道互换。

> 设计建议：故障统一用 `Fault` 扩展（新增 kind + 参数），每类故障给出
> **解析特征 + 幅值/严重度**，并在 metadata 里带唯一故障标签。默认把
> **轴承 / 定子匝间短路 / 缺相**列为 P0 先做（与鲁棒性 R6 联动）。

## 3.5 随机退化注入（方向 3 增强 · 8/17 新增需求）

### 背景（为什么不做线性退化）

现有 `degradation`（缓变劣化）是**线性斜坡**注入，严重脱离实际：
真实退化是**随机过程**——磨损既有确定性趋势又带随机性（随机游走）、
退化后电流波动本身变大（方差失稳）、早期故障**间歇性**时好时坏、
后期**加速恶化**（浴盆曲线）。

> 判断目标不是"捕捉故障瞬间"，而是**识别渐进退化的轨迹**——这需要一个
> "带随机性的退化数据集"作为先验，供趋势检测 / 健康度 / 基线漂移(R8) 验证。
> 本小节把 `degradation` 从线性升级为**四层随机退化模型**。

### 目标：四层随机结构

| 层 | 模型 | 物理对应 |
|----|------|----------|
| ① 漂移 + 随机游走 | $d(t)=d_0+\mu t+\sigma_w W(t)$（维纳过程） | 磨损有趋势又带随机性 |
| ② 波动率增大 | $\sigma(t)=\sigma_0(1+k_d\,d(t))$ | 退化后电流波动变大（方差失稳） |
| ③ 间歇性闪烁 | 马尔可夫开关 $s(t)\in\{0,1\}$ | 早期故障时好时坏 |
| ④ 加速退化 | 浴盆曲线 $d(t)\propto e^{\lambda t}$ | 后期越坏越快 |

### 退化注入通道（不只改一个幅值）

```
退化水平 d(t) ──→  RMS 基线（缓慢漂移）
             ──→  MCSA 边带能量（转子/轴承退化特征，呼应 FFT 频带拆解）
             ──→  谐波 / THD 水平
             ──→  噪声底 / 波动率 σ
             ──→  间歇开关（马尔可夫）
```

> 输出必须带 **ground-truth 退化曲线 $d(t)$**（逐时刻退化水平），
> 供后续"基线 + 置信区间 + 累积度量"判断方法做定量验证。

### 需要电气工程师确认

- **RD-01** 真实退化的**典型时长尺度**？（分钟 / 小时 / 天——影响仿真时间
  与物理时间的压缩比，例如 1 天退化压缩成 5 分钟仿真）
- **RD-02** 各退化通道的**相对强度**（RMS 漂移 vs 边带增长 vs THD 变化），
  给个大致量级，或按默认（RMS ±5~15% / 边带 +6dB / THD +2~3 个点）？
- **RD-03** 退化曲线是否需要**可复现**（固定 seed 生成 + 批量随机抖动）？默认支持。
- **RD-04** 是否需要在**退化基础上叠加事件型故障**（退化进程中偶发堵转 / 缺相，
  模拟"带病运行中再出突发"）？默认支持。

> 设计建议：新增 `DegradationInjector`（独立于现有 `Fault`，四层模型 + seed 复现 +
> 输出退化曲线 ground truth）；事件型故障仍走现有 `Fault`，可时间上叠加。

## 4. 数据契约对齐（方向 4）

### 现状
metadata 含：`fs / duration / f1 / adc_bits / full_scale / snr_db / channels /
sync / clip_ratio / units / faults`。

### 目标
完整落地《采集侧确认清单》8 参数契约：**三相同步 · 采样率 · 位深 · 标定 ·
满量程/削波 · 时戳/连续性 · 帧封装/CRC · 噪声底**，并输出为规范 metadata / JSON。

### 需要电气工程师确认

- **CT-01** **采样率最终确认值**？`config.yaml` 是 16kSPS，架构文档提到 50kSPS。
  仿真默认按哪个？（涉及内存/性能，建议 16k 起步）
- **CT-02** **传感器类型与量程**：CT / 霍尔 / 罗氏线圈？额定电流（A）？
  满量程对应多少 A？（决定 `full_scale` 与 `current_scale`，当前 config 是
  `current_scale=1.0 A/V`、`adc_vref=3.3V`）
- **CT-03** **标定**：合成数据是否需要带"标定系数/单位换算链"
  （ADC 码值 ↔ 电流 A）？默认输出 `A (per-unit)` + 换算链，够用吗？
- **CT-04** **帧封装 / CRC**：仿真数据是否需要模拟帧头/帧尾/CRC 校验字段
  （用于测 R5 时戳/CRC 链路）？默认加一个轻量帧结构？
- **CT-05** **时戳/连续性**：默认完美连续时戳。是否需要可注入"丢样/抖动"
  （与方向 6 混沌注入联动）？
- **CT-06** **噪声底**：白高斯 vs 实测噪声底（含工频干扰/谐波背景）。
  默认 `snr_db=60` 白噪声，是否要加"谐波背景 + 低频抖动"更真实？

> 设计建议：metadata 升级为**分层结构**（contract / generation / faults / quality），
> 并提供 `export_contract_json()` 直接产出契约 JSON，供数据体检 QA 脚本（TODO-D）比对。

## 5. 流式 / 连续生成（方向 5）

### 现状
`generate_dataset` 一次性批量生成 (N,3)，无法流式喂给环形缓冲 / 看门狗 / 触发引擎。

### 目标
提供**流式接口**（按帧/按块产出），支持**长时间/无限循环**场景（soak 24h 测试），
并保留批量接口兼容。

### 需要电气工程师确认

- **ST-01** 流式步长对齐帧结构？默认按 `256 点/帧，128 点步长`（快路径窗口）
  与 `config.window` 一致，可以吗？
- **ST-02** 是否需要**无限循环**（soak）模式？循环点：整段重放 vs 动态实时计算？
  默认"按场景时间片循环重放 + 每圈微抖"。
- **ST-03** 流式模式下故障如何**动态注入/切换**？按时间片调度（同批量逻辑）即可？
- **ST-04** 是否需要支持**断点续读**（从指定时间点继续生成），用于复现某帧问题？

> 设计建议：新增 `CurrentStreamSimulator` 类（`next_frame()` / `reset()` /
> `seek(t)`），内部复用波形生成逻辑；批量接口保持不动。

## 6. 混沌注入（方向 6）

### 现状
无。`08_鲁棒性/鲁棒性清单.md` 4.2 已定义注入类型，但仿真器没有产出能力。

### 目标
仿真器能产出"被污染"的数据段（配合鲁棒性测试工具做 chaos runner），
验收标准：进程存活 100%、每类有"标记 + 降级 + 恢复"路径。

### 需要电气工程师确认

- **CH-01** 混沌注入作为 `Fault` 的一种（复用时间线机制），还是独立
  `ChaosInjector` 接口？建议独立（混沌是"数据质量"问题，不是"设备故障"）。
- **CH-02** 注入类型与 08 清单对齐：`NaN / ±Inf / 断线(常值) / 直流偏置 /
  ADC 削波 / 丢样 / 相位错序 / 突发异常` —— 全部支持？还是有取舍？
- **CH-03** 每类混沌需要**注入时机**：帧级 / 窗级 / 事件后 / 重启后？
  默认"帧级 + 事件后"两类先做。
- **CH-04** 是否需要**恢复验证**（注入后回到正常段，验证自动复位）？默认支持。

> 设计建议：`ChaosInjector` 输出"污染段 + quality flag 真值"，
> 供鲁棒性测试断言"标记 + 降级 + 恢复"。

## 6.5 电流+电压交叉验证（v0.3 新增方向，请电气确认）

只测电流难以区分"供电侧问题"(电压先变) 与"电机侧问题"(电流先变)。
软件侧已能生成对齐的三相电压并做 Z=V/I / cosφ 交叉验证（`generate_vi_dataset` + `cross_validate.py`），
但**采集硬件是否同时具备电压通道**需电气确认：

- **VI-01** 设备侧是否已/打算装**电压传感器**（或直接采 VFD 输出电压/母线电压）？量程？
- **VI-02** 若只测电流，交叉验证退化为"仅电流多特征"，供电侧问题会漏——是否接受？
- **VI-03** 电压采样点：电机端子 / VFD 输出 / 电网进线？三相是否同步采？
- **VI-04** 数据契约需从 3 通道（电流）扩展为 6 通道（3 电流 + 3 电压），确认带宽/ADC 是否够。
