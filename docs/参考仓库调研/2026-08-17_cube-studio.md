# data-infra/cube-studio — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/data-infra/cube-studio
> **技术栈**：Kubernetes + Python(Flask/FAB) + React/Antd + 大量 job-template 算子
> **定位**：国产化、云原生的一站式 AI/MLOps 平台（MIT）
> **层级**：云侧集中式平台（非边缘端）

## 一、仓库概览

CubeStudio 是一站式 MLOps / MaaS / 训推 / 算力调度平台：多租户 RBAC、K8s 算力纳管（NVIDIA/昇腾/寒武纪等异构 + RDMA/vGPU）、Notebook 在线开发、拖拉拽 Pipeline 编排、多机多卡分布式训练、超参搜索、模型管理/注册/发布推理（TF/ONNX/Triton/vLLM）、数据标注平台（LabelStudio 自动化标注）、数据集管理、大模型 SFT/RLHF 微调、LLMOps、私有知识库、AI 应用商店、边缘计算、国产芯片支持。

定位：位于"大数据平台"与"智能体开发平台"之间，贯通**数据清洗→标注→在线开发→训练→评估→推理发布→算力调度**全链路。

## 二、值得借鉴（远期，非当前）

### 1. 模型注册 / 版本化（model-register）
对应数据飞轮闭环"重训→注册→部署" + M3 模型版本管理。
- 借鉴：`model-register` 任务模板用「模型名 + Run ID」防重复注册，统一管理版本/路径/指标/框架/推理框架，
  提供「训练→注册→部署」一体化流程。
- 为什么：等 M3（NPU 推理闭环）做模型版本化时是现成范式。

### 2. 标注平台 + 自动化标注（LabelStudio 集成）
对应数据飞轮"触发切片 → 人工确认 → 积累标签"环节。
- 借鉴：LabelStudio 集成 + 模型辅助预标注（目标识别/分类/OCR 等）。
- 为什么：我们的触发事件切片正是待标注数据；标注平台接入是数据飞轮标签积累的落地工具。

### 3. Pipeline 节点化（数据→训练→评估→注册→部署）
对应"特征→训练→导出→RKNN"的可复现流程。
- 借鉴：任务模板 + 拖拽 DAG，每步一个算子、可复现可重跑。
- 为什么：我们目前的训练/导出是脚本，做成 pipeline 节点便于重跑与追溯。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| K8s / 多租户 / 算力租赁 / 计量计费 | 单板边缘场景，不需要部署整套云平台 |
| Notebook / 拖拉拽编排平台 | 我们算法栈是固定 pipeline，不是开放编排 |
| 大模型微调 / LLMOps / 私有知识库 | 与电流诊断无关 |
| 异构算力调度 / RDMA / vGPU | 单板无此需求 |

## 四、结论

**借鉴度 ★★ 中（远期）**。它和本项目不在一个层面（云侧集中式 AI 平台 vs 端侧嵌入式算法），
**短期不碰**；中期（M2–M3 数据飞轮成型后）仅复用两点：**模型注册/版本化 + 标注平台接入**。
届时参考其设计，而非部署其平台。
