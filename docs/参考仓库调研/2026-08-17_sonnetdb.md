# IoTSharp/SonnetDB — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/IoTSharp/SonnetDB
> **技术栈**：C#/.NET + 嵌入式 + HTTP/2 帧协议 + MQTT + 多语言连接器 + MIT（82★ / 14 fork）
> **定位**：多模型数据引擎（时序/关系/KV/文档/全文/向量/对象存储/消息队列八模型一进程）
> **契合度**：★★★ 高（嵌入式时序存储 + 内建 MQTT 落库，特征日志/上行通道存储选型参考）

## 一、仓库概览

SonnetDB 是面向工业 IoT、边缘应用与 AI 数据负载的多模型数据引擎：把八类数据能力统一进同一个引擎，通过 SQL、标准 API 和管理工具访问。核心价值是"统一"——八种模型共用一个进程、一套权限/运维边界、一套备份恢复机制和一个管理后台。

核心能力（README 核实）：
- **八种数据模型**：时序（设备指标/工业采集/时间窗口聚合/压缩/Retention）、关系表、KV/缓存、JSON 文档、全文检索（BM25）、向量检索（HNSW+Hybrid Search）、对象存储（S3 兼容）、消息队列（SonnetMQ）
- **嵌入式**：`Tsdb.Open(...)` 进程内打开数据库目录；**服务端**：Docker/HTTP API/Web Admin
- **内建 MQTT broker**（设备直连落库）+ 外部 MQTT client（订阅现有 EMQX/Mosquitto）；**Sparkplug B** 接入
- 批量写入：**Line Protocol / JSON ingest**（InfluxDB 风格）
- **全模型二进制帧协议**（HTTP/2，时序批量写列式紧凑直传、流式列式分块回传）
- **WAL 三级落盘**（进程内缓冲 / OS page cache / 每批 fsync），已 flush segment 任何崩溃不丢
- **Parity 套件**：每日与 PostgreSQL/MongoDB/InfluxDB/VictoriaMetrics/Redis/Qdrant/MinIO/NATS JetStream/Meilisearch/ClickHouse 对齐能力/可靠性/算法准确度
- 接入：.NET 生态（ADO.NET/EF Core/IDistributedCache）、CLI、VS Code 扩展、多语言连接器（C/Go/Rust/Java/Python/VB6/PureBasic）、AI/Agent（Web Copilot、MCP 工具入口）
- 边界诚实：单机无 HA；多模型是能力组合不是每项第一；SQL 是子集

## 二、值得借鉴（为什么）

### 1. 嵌入式时序 + 内建 MQTT 落库（边缘存储选型参考）
- 借鉴：嵌入式（进程内打开目录）+ 内建 MQTT broker 让设备直连落库。
- 为什么：**正是边缘特征日志/断网续传的存储选型**——"一个组件覆盖时序+KV+缓存+消息"的思路，比我们当前纯 SQLite 更完整，可作 M1 存储层升级方向的参考（SQLite → 嵌入式时序引擎）。

### 2. Line Protocol / JSON 批量写入
- 借鉴：InfluxDB 风格批量写入（Line Protocol/JSON ingest）。
- 为什么：我们特征日志落库/上行的写入格式可参考 Line Protocol（紧凑、批量、自带时间戳）——比逐行 INSERT 高效。

### 3. WAL 三级落盘 + 崩溃安全
- 借鉴：WAL 落盘强度分级，已 flush 数据崩溃不丢。
- 为什么：我们断网续传/本地缓存要求"零丢失"，其 WAL 分级策略（性能 vs 可靠性权衡）是工程参照。

### 4. Parity 对齐套件（验证方法论）
- 借鉴：与开源组件按能力/可靠性/算法准确度做红绿门槛对齐。
- 为什么：我们验证工具可借鉴"与标准实现对齐 + 红绿门槛"的验证方式（如 FFT 与 scipy 对齐、滤波与 sosfilt 对齐——已在做，可更系统化）。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| C#/.NET 实现 | 我们 Python 栈 |
| 八模型全量（向量/对象存储/文档） | 我们只需时序 + KV + 消息 |
| 二进制帧协议（HTTP/2） | 我们轻量 JSON 即可 |
| 向量检索/全文 | 暂不需要 |
| 单机无 HA 限制 | 与我们一致，无碍 |

## 四、结论

**借鉴度 ★★★ 高**。它是"嵌入式多模型存储"的完整实现，对我们的价值在**边缘存储选型与写入格式**：
① 嵌入式时序 + 内建 MQTT 落库（M1 存储层升级方向参考）；
② Line Protocol 批量写入（特征日志格式）；
③ WAL 崩溃安全分级（断网零丢失工程参照）。
C# 栈不部署。建议纳入特征日志/存储架构（freeioe/BetterIOT 之外）的选型参照。
