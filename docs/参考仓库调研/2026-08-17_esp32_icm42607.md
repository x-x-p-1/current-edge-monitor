# Newdawn01/esp32_icm42607 — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/Newdawn01/esp32_icm42607
> **技术栈**：ESP32-S3 + Arduino/ESP-IDF + FreeRTOS + ESPAsyncWebServer + WebSocket + PlatformIO + Python 网关 + MIT
> **定位**：工业级振动监测边缘节点（传感器 → 边缘计算 → Web 可视化全链路闭环，无需上位机）
> **契合度**：★★★ 高（自适应阈值/基线工程方法论直接参考）

## 一、仓库概览

基于 ESP32-S3 + ICM-42607-P 六轴 IMU（SPI，800Hz）的工业级振动监测系统，实现"传感器→边缘计算→Web 可视化"全链路闭环。所有特征计算在设备端完成，无需上位机。

核心特性（README 核实）：
- **15 参数边缘计算**：速度 RMS、峭度、加速度峰值、位移峰峰值（三轴×4 + 温度×3），全部设备端实时完成
- **工业级信号处理**：二阶 Butterworth HPF、**温度漂移补偿（四层防御）**、**3σ 离群值剔除**、EMA 输出平滑、**报警延迟确认**
- **自适应阈值**：EMA 基线追踪 + 温度感知，设备自动适应不同工况，无需人工调参
- 即插即用 Web：内置完整 SPA，浏览器即看实时数据/趋势/时域波形/**FFT 频谱**
- 多设备管理：局域网自动发现（mDNS + IP 扫描）、统一仪表盘、批量 OTA
- 本地网关工具（vibe-gateway，可打包 exe）

架构：双任务（sampler_task 采集 / web_task DSP+Web），WebSocket 二进制推送（53 字节特征包），前端纯 radix-2 FFT + 汉宁/汉明窗 + dB 刻度。

## 二、值得借鉴（为什么）

### 1. EMA 基线追踪 + 温度感知的自适应阈值（直接方法论参考）
- 借鉴：`baseline_manager.cpp` —— EMA 基线追踪 + 温度感知，设备自动适应不同工况。
- 为什么：与我们的 `TriggerEngine`（EWMA 自适应基线 + K·σ 统计触发）**异曲同工**，是同一思路在嵌入式端的独立实现，可交叉核对参数策略（基线更新率、自适应触发、释放机制）。

### 2. 四层温度漂移补偿
- 借鉴：上电校准 + 在线学习 + 温补 + 基线感知四层防御。
- 为什么：**电流互感器/模拟前端同样有温漂问题**——这套分层的漂移补偿框架（上电校准→在线学习→温补→基线感知）可直接映射到我们直流偏置/基线漂移处理。

### 3. 紧凑二进制特征包 + WebSocket 推送
- 借鉴：53 字节特征包二进制推送。
- 为什么：对应我们看板/上行通道的序列化设计，特征包紧凑化思路可参考（vs JSON 快照的带宽对比）。

### 4. 边缘侧特征计算 + 纯前端 FFT
- 借鉴：15 参数全部设备端算完，前端只做展示（前端 radix-2 FFT）。
- 为什么：印证"特征上移、原始数据按需取"的架构；纯前端 FFT 也是我们 HTML 看板可用的低成本频谱展示方案。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| ESP32 固件/FreeRTOS 双任务 | 我们目标是 RK3588/A733（Linux），非 MCU |
| 振动三轴特征（RMS/峭度/峰值） | 我们诊断对象是三相电流，特征域不同（仅 RMS/包络等通用特征可参考） |
| mDNS/OTA 多设备管理 | 我们的多设备/OTA 是上位机侧，非端侧 Web |
| 每分钟唤醒节能策略 | 我们要求连续实时采集，无休眠需求 |

## 四、结论

**借鉴度 ★★★ 高**。它是"边缘节点自包含信号处理"的完整范例，与我们的交集在**信号特征计算与阈值工程**：
EMA 自适应基线、温度漂移四层补偿、3σ 剔除、报警延迟确认、特征包二进制推送。
建议把 **baseline_manager 的基线追踪 + 温度感知**和**四层温补**纳入鲁棒性（10_鲁棒性）与触发引擎的参考项。
