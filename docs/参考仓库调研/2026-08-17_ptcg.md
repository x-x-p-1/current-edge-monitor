# David-gby/PTCG- — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/David-gby/PTCG-
> **技术栈**：Python + YOLOv8（分割/精修/Pose）+ OpenCV + SQLite + Web（企业/管理端）+ systemd/Caddy
> **定位**：CardScope 卡牌居中检测平台（视觉质检 + 手动修正反馈 + 模型再训练闭环）
> **契合度**：★★ 中（数据飞轮又一个落地形态）

## 一、仓库概览

CardScope 是用于卡牌居中检测（centering）的 Web 平台，面向 TCG 卡牌（如 PTCG）量产质检。上传实拍照片后自动完成**外框检测、透视矫正、内框检测、居中偏差计算与合格判定**。当前版本 0.8.1，已生产部署（Ubuntu + systemd + Caddy 反代）。

核心能力（README 核实）：
- **外框检测与矫正**：分割模型粗定位 + 四边高分辨率条带精修（抗阴影/套壳）+ 角点透视矫正
- **内框检测**：矫正图内框四边，计算居中度与偏差百分比（默认阈值 5%）
- **参考图配准**：实拍图 + 标准图归一化配准，给出偏移量与置信度
- **手动修正与反馈**：测试人员可调整外框角点与内框参考线，提交修正进入反馈审核队列
- **模型再训练**：管理员审核通过的标注导出到训练池 → 自动训练 → 模型上线仍由管理员操作
- **访问控制**：企业只能访问自己的结果；分享链接带令牌保护
- 多模型管线（`CardFramePipeline`）：outer_seg / outer_line_refiner / outer_pose / inner_frame_yolo / inner_frame_edge_refiner（含左/上边商标干扰专项专家模型）

## 二、值得借鉴（为什么）

### 1. 手动修正 → 审核 → 训练池 → 再训练（数据飞轮完整闭环）
- 借鉴：测试人员修正几何 → 反馈队列 → 管理员审核 → 导出训练池 → 自动训练 → 管理员上线。
- 为什么：这是**又一个"数据飞轮"落地形态**（与 aiotec 误报反馈互相印证），且比 aiotec 更完整：
  **人工修正 → 审核门禁 → 训练池 → 自动训练 → 上线管控** 五级闭环。我们 M2 数据飞轮（切片→人工标注→积累→重训）可参考它的"审核门禁 + 上线由管理员管控"设计。

### 2. 精修/回退的多模型管线
- 借鉴：粗定位 + 高分辨率条带精修 + 专家模型按置信度门槛启用 + 回退链路。
- 为什么：与我们"多特征联合 + 置信度门控"思想同构——用多级模型 + 置信度做稳健判定（边缘精修回退链路的组织方式可参考）。

### 3. 阈值判定 + 可视化输出
- 借鉴：偏差阈值（5%）判定不合格 + 可视化结果；企业隔离访问。
- 为什么：对应我们健康度/判定阈值的产品化方式（阈值可配置 + 结果可视化 + 多租户隔离）。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| 卡牌居中检测算法（透视/内框） | 图像质检，与电流诊断无关 |
| 多模型视觉管线 | 视觉域；仅"置信度门控 + 回退"的组织思想可提 |
| Web 多租户/企业隔离 | 我们单站部署为主，无多租户需求 |
| Caddy/systemd 生产部署 | 我们目标 RK3588 部署，部署形态不同 |

## 四、结论

**借鉴度 ★★ 中**。它是"视觉质检 + 数据飞轮闭环"的成熟产品，与我们交集在**数据飞轮工程**：
① 手动修正 → 审核门禁 → 训练池 → 自动训练 → 上线管控（M2 数据飞轮的五级闭环参考）；
② 多级模型 + 置信度门控 + 回退的稳健判定组织。
视觉算法本身不借鉴。建议纳入 M2 数据飞轮设计时的参考（与 aiotec 误报反馈互补）。
