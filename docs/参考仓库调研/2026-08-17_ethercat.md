# anviod/EtherCAT — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/anviod/EtherCAT
> **技术栈**：Go（纯 Go，零 CGo / 零内核模块）+ 中英双语文档 + GitHub Pages
> **定位**：工业以太网协议 EtherCAT 的纯 Go SDK（edgeCore 作者配套项目）
> **契合度**：★ 低（协议层 SDK，仅方法论 2 点）

## 一、仓库概览

EtherCAT（Ethernet for Control Automation Technology）是倍福（Beckhoff）的工业实时以太网总线协议，
用于运动控制/机器人/半导体制造等实时场景。本仓库是它的**纯 Go 软件实现**，当前定位为 Protocol Library，
下一阶段目标是 ETG 规范的工业级 Master（尚未实现）。

分层架构：
```
ecad   ESC 从站控制器寄存器地址常量 (ETG.1000)
  ↓
ecfr   帧/数据报编解码（零分配热路径）
  ↓
ecmd   命令执行 + 帧调度 + goroutine 安全多路复用
  ↓
etransport(UDP) / ecee(EEPROM) / internal/sim(从站/总线模拟)
eni     ESI 从站信息 XML 解析（独立）
```

亮点：225+ 测试 / 覆盖率 74–92%；**L2 从站/总线纯软件模拟**（无需真实硬件做协议级测试）；
性能实测（RK3588s）：最短稳态总线循环 ~4μs、热路径占 100μs 周期 <0.5%；
自带 CLI + 中英双语文档。成熟度自评诚实：Frame 库⭐⭐⭐⭐⭐、SDK⭐⭐⭐⭐、Master/Stack 层（AL 状态机/PDO/Mailbox/DC）未实现，与 SOEM/IgH/TwinCAT 差距明显。

## 二、值得借鉴（方法论，与协议无关）

### 1. 无硬件协议模拟测试（internal/sim 从站/总线模拟）
- 借鉴：没有真实从站也能做协议级/回归测试，且 CI 集成。
- 为什么：与我们的"仿真器打底、管线自检"是同一理念——用软件模拟替代硬件做回归验证，
  印证我们 00 仿真器 + 07 自检工具的方向是对的。

### 2. 性能预算 + 基准驱动
- 借鉴：每操作 ns / 分配数都量化（热路径零分配、<0.5% 周期占比有基准背书）。
- 为什么：对应我们"每帧 <1.8ms、FFT 4s 窗 2.5ms"的性能预算思路，性能要量化可验证而非拍脑袋。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| EtherCAT 协议本身 | 我们采集三相电流（ADC 直采 + 可能 VFD/PLC 遥测）；变频器走 Modbus/模拟量，不走 EtherCAT |
| 完整 Master / AL 状态机 / PDO / Mailbox | 未实现，且与我们无关 |
| Go 技术栈 | 我们 Python 算法栈 |
| 与 SOEM/IgH 对比差距明显 | 无需跟它的协议深度 |

## 四、结论

**借鉴度 ★ 低**。它是"工业总线协议 SDK"，与电流监测不在一条线；除非将来接高端伺服/VFD 的
EtherCAT 遥测才可能用到（大概率用不上）。唯一值得记住的是**"软件模拟从站做测试 + 性能基准量化"**
两个工程方法论——恰好印证我们仿真器 + 性能验证的方向是对的。
