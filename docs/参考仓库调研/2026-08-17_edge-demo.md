# qianyu-web/edge-demo — 参考报告

> **定位**：工业边缘计算参考实现（PLC 采集 → 边缘处理与异常检测 → 断网缓存补传 → 云端可视化）
> **契合度**：★★★ 高（对标 M1 工程实现 + 断网续传第四个印证）

## 一、仓库概览

可一键启动的工业边缘计算参考实现，覆盖完整数据链路：**PLC 数据采集（Modbus TCP）→ 边缘实时处理与异常检测 → 断网本地缓存与恢复补传 → 云端可视化**，并附带 OpenVINO 加速的视觉质检示例。适用：学习工业物联网/边缘计算、方案演示。

架构链路：
```
PLC 模拟器 ──Modbus/TCP──▶ 边缘处理器 ──MQTT──▶ EMQX ──MQTT──▶ Node-RED 看板
(plc_simulator.py)          (edge_processor.py)   (broker)      (dashboard)
```

核心实现（README 核实）：
- **采集层**：`pymodbus` 以 Modbus TCP 读 PLC 保持寄存器，模拟**振动/温度/电流**三路传感信号（含随机尖峰故障注入）
- **边缘层**：滑动窗口计算均值/标准差，**阈值 + 3σ 双重异常判定**；数据先落 SQLite，再异步上报
- **传输层**：EMQX 作 MQTT Broker，解耦边缘与云端
- **应用层**：Node-RED 订阅 MQTT，实时渲染曲线/状态/告警
- **断网容错**：本地 SQLite 缓存，网络恢复后按序自动补传，**零数据丢失**；已上报数据保留 7 天自动清理
- **视觉扩展**：YOLOv8 + OpenVINO 实时推理（摄像头/图片输入）

技术栈：采集 Python/pymodbus；边缘 Python/SQLite；消息 EMQX/MQTT/paho；云端 Node-RED；视觉 Ultralytics/OpenVINO/OpenCV；部署 Docker Compose + GH Actions。

## 二、值得借鉴（为什么）

### 1. 「滑动窗口统计 + 阈值+3σ 双重异常判定」的工程落地
- 借鉴：边缘层用滑动窗口均值/标准差做统计基线，再叠加绝对阈值 + 3σ 双重判定。
- 为什么：与我们「基线 + 置信区间 + 累积度量」方向**同源**，且是可直接对照的最小实现（含故障注入模拟）。

### 2. 断网补传的完整闭环（第四个印证）
- 借鉴：断开 MQTT → 边缘侧本地记录 → 恢复连接 → 离线数据按序补传 → 看板曲线无缺口。
- 为什么：freeioe/BetterIOT/edgeCore/aiotec 之外**再次印证**"断网不丢数据"是边缘网关行业标配；且提供了可演示的验收路径（docker stop/start emqx）。

### 3. 离线缓冲 TTL 策略
- 借鉴：已上报数据保留 7 天后自动清理。
- 为什么：为「本地缓存 → 上行通道」的容量管理提供量化参考（缓存保留窗口、清理策略）。

### 4. 遥测驱动抽象 + 通道配置
- 借鉴：`CHANNELS` 配置（reg 寄存器地址 / limit 绝对阈值 / window 滑动窗口）驱动多路采集。
- 为什么：印证「统一驱动抽象 + 物模型」模式（同 BetterIOT/LotusBridge），且可平滑切换真实 PLC（环境变量 MODBUS_HOST/PORT）。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| 异常检测只做"单点超限" | 没有频域/退化建模——这正是我们超出它的部分（MCSA 边带/THD/噪声底） |
| 视觉质检（YOLOv8/OpenVINO） | 视觉场景，与电流诊断无关 |
| Docker Compose 编排方式 | 我们目标 RK3588 原生/轻量部署，非容器优先 |
| Node-RED 看板 | 我们已有自定义 HTML 看板；Node-RED 作为拖拽规则引擎远期可选 |

## 四、结论

**借鉴度 ★★★ 高**。它几乎就是 M1 + 数据飞轮上行通道的最小可对照实现：
采集（含电流通道）→ 滑动窗口统计 + 阈值/3σ 异常 → 本地缓存断网补传 → 可视化。
可直接对照的点：异常判定阈值策略、断网补传验收路径、离线缓冲 TTL、遥测通道配置。
路线图（EdgeX 重构 / OPC UA / 模型热更新）与我们远期方向一致。**建议纳入英文批次核心参考**。
