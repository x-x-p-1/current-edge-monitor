# pnoker/iot-dc3 — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/pnoker/iot-dc3
> **技术栈**：Java 21 + Spring Boot 4 + Spring Cloud 2025 + Spring AI + PostgreSQL/TimescaleDB/pgvector + RabbitMQ + gRPC + Vue3 + AGPL-3.0（815★ / 231 fork）
> **定位**：多协议、云原生、AI 赋能的工业物联网平台（28 协议驱动 + Driver SDK + AI 智能体中心）
> **契合度**：★★★ 高（采集驱动抽象 + 物模型 + 告警规则的最工业化实现）

## 一、仓库概览

IoT DC3 是多协议、云原生、AI 赋能的开源工业物联网平台，面向智能体演进。六层微服务架构：客户端 → 网关 → 四大中心服务 → 消息总线 → 28 个协议驱动 → 现场设备。

核心能力（README 核实）：
- **28 协议驱动**：工业（Modbus TCP/RTU、OPC UA/DA、S7、BACnet/IP、EtherNet/IP、Omron FINS、Mitsubishi MELSEC、IEC 60870-5-104、SL651、DLMS）、IoT（MQTT、CoAP、LwM2M、HTTP、BLE、Zigbee）、数据桥接（MySQL/PG/Oracle/SQL Server）、基础通信（TCP/UDP/串口/SNMP/CAN）、仿真（Virtual）
- **Driver SDK**：快速开发自定义协议驱动并注册进运行时平台
- **实时数据引擎**：驱动采集 → RabbitMQ 异步 → 时序存储（TimescaleDB+pgvector+AGE）→ 规则引擎多级告警 → 事件溯源
- **AI 智能体中心**（Spring AI）：自然语言查询设备/读写点位/告警根因分析/数据洞察图表；支持 GPT/Claude/DeepSeek/Qwen
- **云原生**：Spring Cloud Gateway + gRPC/Protobuf + 无状态水平扩展 + 故障隔离
- 多租户、JWT+RBAC、TLS、审计日志；Vue3 前端

## 二、值得借鉴（为什么）

### 1. Driver SDK + 协议驱动注册模式（采集驱动抽象的工业化实现）
- 借鉴：28 个现成驱动 + Driver SDK 支持自定义驱动注册进平台。
- 为什么：这是「采集驱动抽象 + 物模型」**第三次印证且最工业化**的实现——我们 M1 若要做 VFD/PLC 多协议接入，其"驱动即插即用 + 注册"模式是成熟参照。

### 2. 物模型 + 规则引擎多级告警
- 借鉴：设备/点位物模型 + 规则引擎多级告警与通知。
- 为什么：对应我们「按工况打标签 + 健康度 + 分级告警」——物模型规范与告警规则编排是产品化参照。

### 3. 驱动采集 → 消息总线 → 时序存储的链路
- 借鉴：采集异步发 RabbitMQ，时序存储，事件全留痕。
- 为什么：印证「采集解耦 + 时序落库 + 事件溯源」链路（同 StreamPipes/iotStudio），对应我们特征日志 + 上行通道。

### 4. AI 智能体中心（远期）
- 借鉴：自然语言查设备/告警根因分析/数据洞察图表，多模型兼容。
- 为什么：我们远期"AI 诊断助手"可直接参考其 Tool Calling + 访问控制 + 告警分析的落地方式。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| Spring Cloud 微服务栈 | 重型，不匹配 RK3588 轻量部署 |
| gRPC/水平扩展/多租户 | 单站边缘场景不需要 |
| PostgreSQL/TimescaleDB | 我们边缘侧 SQLite 优先 |
| 具体驱动实现（28 个） | 我们只需 Modbus/OPC UA 等少数，借鉴 SDK 模式而非搬运 |
| AGPL 许可 | 不部署其代码，仅借鉴设计 |

## 四、结论

**借鉴度 ★★★ 高**。它是「多协议接入 + 物模型 + 告警规则 + AI」的一体化工业平台，对我们最有价值的是 **Driver SDK 驱动注册模式**（采集驱动抽象的最工业化参照）和**物模型 + 规则告警**（健康度/分级告警产品化参照）。
Java 重栈不部署。建议与 BetterIOT/LotusBridge 并列作为「采集驱动抽象」结论的权威佐证。
