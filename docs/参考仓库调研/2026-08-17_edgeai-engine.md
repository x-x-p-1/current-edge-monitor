# ExpressGit/EdgeAI-Engine — 参考报告

> **调研日期**：2026-08-17
> **仓库**：https://github.com/ExpressGit/EdgeAI-Engine
> **技术栈**：Python + PyTorch + ONNX + RK3588/昇腾量化适配 + YOLO/分割/姿态/ArcFace + 传统图像分析
> **定位**：机器视觉边缘计算的成熟应用，适配 RK/Ascend 芯片，提供模型训练 + 量化源码
> **契合度**：★★ 中（M3 RKNN 量化路径参考；应用是视觉，算法本身不借鉴）

## 一、仓库概览

"机器视觉边缘计算的成熟应用"仓库，基于 RK3568/RK3588 的 Arm-Linux 芯片架构，历经钢铁、金矿、石油、危化品、安防、电力能源等领域大量工业落地。两部分：**模型训练源代码**（PyTorch）+ **模型量化源代码**（RK 瑞芯微 / Ascend 昇腾）。

文件结构：
- `Train/`：目标检测（训练/推理/验证）、实例分割、姿态检测（推理）、ArcFace（训练/推理/验证）、传统图像分析（帧差、像素均值）
- `Quantization/`：RK3588 目标检测量化代码、RK3588 实例分割量化代码（含训练数据转化步骤）
- `tools/Annotation_tools`：数据标注工具

应用栈（README 核实）：人员管理（安全帽/反光衣/人脸/跌倒/口罩/计数/离岗/聚集/入侵/徘徊/睡岗/手机/抽烟/工服）、险情防控（明火/明烟/静电夹/电瓶车/灭火器）、车辆管理、钢铁（板材测量/跟踪）、油田（漏油/滴液）、金矿（停机/锚杆）、其他（黑屏/轨道异物/皮带偏离/垃圾/货架动作/移动侦测）。

技术栈观点（README）：光谱分析技术（帧差、像素均值）常能以低成本替代 AI 方法，省去人工标注——与"简单方法优先"理念一致。

## 二、值得借鉴（为什么）

### 1. RK3588 模型训练 → RKNN 量化适配的完整路径（M3 备查）
- 借鉴：`Quantization/` 提供 RK3588 目标检测/分割的量化代码 + 训练数据转化步骤。
- 为什么：我们 M3 计划用 RKNN NPU 推理，届时模型量化（训练模型 → RK 量化 → 板端加载）的路径可直接参考。

### 2. 传统方法优先的取舍观
- 借鉴：帧差/像素均值等传统方法以低成本达到好效果，替代 AI 并省去标注。
- 为什么：与我们的理念一致——能用简单确定性算法（FFT/阈值/统计）解决的，不引入复杂模型；可作为 M3 模型选型的对照原则。

### 3. 商业落地场景清单（远期参考）
- 借鉴：钢铁/油田/金矿等工业场景的"问题→方法→精度"映射表。
- 为什么：工业检测的工程化成熟度参考（虽然场景不同，但"如何把算法做成可交付产品"的路径有参考）。

## 三、不需要借鉴（为什么）

| 点 | 为什么不需要 |
|----|-------------|
| 视觉算法本体（检测/分割/人脸） | 与电流信号诊断无关 |
| 训练代码（PyTorch 视觉） | 我们算法栈是时频域信号处理 + 统计模型 |
| 标注工具/数据集 | 视觉数据标注，与电流切片标注不同域 |
| 昇腾适配（Ascend） | 我们平台是 RK3588 |

## 四、结论

**借鉴度 ★★ 中**。它是"RK3588 上做视觉工业检测"的成熟工程仓库，与我们的交集是**同一硬件平台（RK3588）**。
最有价值的是 `Quantization/` 的 **RKNN 量化路径**（M3 备查），以及"传统方法优先"的取舍观。
应用域不同，不深入借鉴算法本身。
