# 鲁棒性清单 — 连续不停机运行

> **设计原则：算法必须在被监测设备坏之前不能坏。**
>
> M0 仿真只有 30s，而真实部署是 7×24 小时连续运行、以月/年计。
> 仿真跑不出来的问题 —— 数值漂移、内存泄漏、状态机卡死、输入劣化、异常崩溃 ——
> 恰恰是现场最致命的问题。本清单把鲁棒性做成**出厂配置**而非后期补丁，
> 作为 M1 采集层与后续版本的硬性验收项。

## 1. 目标矩阵（威胁 → 防护 → 验收）

| # | 威胁 | 现象 | 防护措施 | 验收标准 |
|---|------|------|----------|----------|
| R1 | NaN/Inf 传播 | 传感器断线 / 除零 / 高增益滤波 → 全链路变 NaN | 每个数值出口做 `np.isfinite` 守卫；特征 / 状态机 / 报警三道闸 | 注入 NaN/Inf 后不崩溃、标记无效帧并跳过，恢复后自动复位 |
| R2 | 除零 / 病态计算 | 停机时 RMS≈0 归一化除零；对称分量零序≈0 | 除零守卫 + epsilon；低于阈值项输出"无效"而非 0 或 ±Inf | 全量故障注入下无未捕获 RuntimeWarning、无 NaN 进入状态机 |
| R3 | ADC 削波 / 饱和 | 过流顶部削平 → 谐波失真假象 | 削波率监测（契约 `full_scale`），超阈标记"失真帧" | 削波率超阈的帧被标记而非误诊为谐波故障 |
| R4 | 传感器断线 / 直流偏置 | 常值 / 直流漂移污染基线 | 断线检测（极低方差 / 固定值）+ 去直流（已有）+ 质量标志 | 断线时进入"输入不可用"降级态，不误报堵转 |
| R5 | 时基抖动 / 丢样 / 乱序 | 帧 CRC 失败、时戳不连续 | 时戳连续性检查 + 丢样计数 + 帧 CRC（数据契约） | 丢样率超阈 → 标记数据段 + 告警"数据质量"，不参与诊断 |
| R6 | 缺相 / 相位错序 | 单相断线 → 三相特征异常 | 三相幅值 / 相序守卫 | 缺相被识别为"缺相"而非"负载异常" |
| R7 | 内存泄漏 / 无界增长 | 特征日志 / 事件聚合 / 看门狗队列随时间增长 | 固定容量环形结构 + 事件聚合窗口上限 + 日志裁剪 | 24h soak 后 RSS 波动 < 5%，无线性增长 |
| R8 | 基线漂移（温漂 / 老化 / 季节） | 基线缓慢移动 → 误报 / 漏报 | DKW 自适应基线（遗忘因子），仅稳态更新，带置信度 | 人为慢漂移注入下误报率保持 ARL 指标，可自动跟随 |
| R9 | 状态机卡死 / 振荡 | 堵转 / 恢复临界点反复跳变 | 迟滞（MonAnL 迁移）+ 状态驻留超时 + 迁移约束 | 临界振荡注入下最终收敛到稳定态，不无限振荡 |
| R10 | 未捕获异常 | 单帧异常 kill 进程 → 设备失去监护 | 全局异常捕获（顶层 try/except）+ 每帧隔离 | 注入任意异常类型，进程存活率 100% |
| R11 | 算法自身卡死 | 看门狗特征停更 | 快路径心跳 + 超时看门狗，超时自动重启流水线 | 模拟卡死 5s 内被检测并自动复位 |
| R12 | 重启状态丢失 | 断电重启后基线归零 | 基线 / 标定 checkpoint 持久化，重启恢复 | 重启后无需重新标定，指标 5 分钟内回到标称 |
| R13 | 队列溢出 / 背压 | 慢路径积压 → 内存爆 / 时延恶化 | 有界队列 + drop-oldest + 快慢路径错峰 | 峰值负载下 p99 帧时延不超预算，无 OOM |

## 2. 分层防护（纵深防御）

```
输入层:  契约校验(时戳/CRC) → 质量标志(削波/断线/丢样/缺相)
信号层:  去直流/带通的数值守卫 → NaN/Inf 清洗 → 无效帧标记
特征层:  每特征 isfinite + 数值域检查 → 无效特征置 NULL + quality flag
模型层:  状态机输入守卫 → 基线置信度门控 → 不确定 → UNKNOWN 而非硬判
输出层:  全局异常捕获 → 优雅降级链(快路径 → 看门狗 → 报警"算法不可用")
```

## 3. 优雅降级链（单点故障不级联）

正常 → 输入劣化（标记 + 继续）→ 特征部分无效（降级算子集）→
算法异常（看门狗报警"算法不可用"）→ 原始旁路（仅保存 + 状态机看门狗）。

**任何一层失败都不允许静默。** 设备可以"糊涂"，但不能"瞎"或"死"。

## 4. 测试方法

### 4.1 长时间压力测试（soak）
- 24h / 72h / 7d，按真实场景负载曲线循环
- 监控：内存 RSS 曲线、无 NaN/Inf、状态机不卡死、帧时延 p99
- 每 6h 注入一次完整故障循环（边带 / 堵转 / 恢复），验证"能犯病、能识别、能恢复"

### 4.2 混沌注入测试（fault injection）
- 注入类型：NaN / ±Inf / 断线(常值) / 直流偏置 / ADC 削波 / 丢样 / 相位错序 / 突发异常
- 注入时机：快路径任一帧、慢路径任一窗、事件后、重启后
- 验收：进程存活 100%；每类注入有明确"标记 + 降级 + 恢复"路径

### 4.3 回归融入
- 全部鲁棒性用例并入 `06_测试与验证`，纳入 pytest 门禁
- `08_鲁棒性/` 提供对应测试工具（soak / chaos runner）

## 5. 验收门禁（全部满足才允许上现场）

- [ ] 24h soak：无 NaN、内存有界、状态机不卡死
- [ ] 混沌注入 10 类全过，进程存活率 100%
- [ ] 自适应基线在漂移注入下误报率达标（ARL）
- [ ] 重启恢复 5 分钟内达标
- [ ] 所有异常路径有日志 + 降级标志，无静默失败
