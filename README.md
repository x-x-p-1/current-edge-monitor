## 项目定位

基于 RK3588S / A733 类边缘板的自研 PCB，采集**三相变频电机的三相电流**，在边缘完成
毫秒级采集、特征提取、触发式异常捕获，并以机器学习实现**过程管理**（设备状态识别、
堵转/负载异常、MCSA 故障诊断），最终形成**数据飞轮**驱动的智能监测闭环。

## 设计理念（v2）

### 1. 数据契约驱动
"原始数据"不是模糊概念，而是一份 8 参数契约：`三相同步、采样率、位深、标定、
满量程/削波、时戳/连续性、帧封装/CRC、噪声底`。所有算法配置（`config.yaml`）
挂在这份契约上，详见《采集侧确认清单》。

### 2. 快/慢路径分窗（ms 响应与 s 诊断的物理解耦）
- **快路径（短窗 ~16ms）**：时域/包络特征 → 状态机（STOP/TRANSIENT/IDLE/LOAD/STALL）→ 触发引擎
- **慢路径（长窗 2~4s）**：频域 / MCSA 边带 / 三相特征 → 诊断与 ML
- 依据：短窗 FFT 分辨率 Δf=fs/N 无法分辨 0.5~2Hz 的 MCSA 边带；而触发需要 ms 级响应。

### 3. 环形缓冲 + 触发（stopping time）+ 切片捕获
设备大部分时间正常，异常是稀有事件。架构 = 全速率环形缓冲常开 + 毫秒级看门狗特征 +
统计触发（ARL 控误报）→ 触发时冻结预触发 + 录后触发，整段切片落盘并携带上下文。

### 4. 特征常存 + 原始默认释放
连续采集 → 提取特征 → 释放原始（省存储）。原始波形仅在**触发事件**与**部署期少量留档**
时保留（= 未来 ML 训练数据）。特征记录自带上下文（时间戳 + VFD 遥测 + 状态）作为 ML 输入。

### 5. 复刻打底 + ML 融合（两轨并行）
- **工程基线（M0~M1）**：规则基线状态机 + AE 异常检测——用成熟算法，不赌研究，保证交付
- **研究轨道（M2+）**：数学家负责 P1 触发统计 / P2 特征规范 / P3 正常建模；
  v2 差异化在变转速鲁棒性、跨机域适应、弱信号提取
- 规则基线的"自适应基线"终极形态由 P3 无监督正常建模接替

### 6. 数据飞轮（零标签起步）
新产品初期无故障标签 → 无监督正常建模（AE / 马氏）→ 异常检测输出健康度+置信度 →
人工确认 → 积累标签 → 重训 → 更准检测。**触发事件切片 = 训练数据**。

### 7. 两阶段板卡策略（性能盈余 → 测量减法）
开发/验证用 RK3588（6TOPS，性能盈余跑通路子），量产用 A733（<400 元，15W + PoE）。
切换 = 改一个配置项（`runtime.backend`）；模型以 ONNX 为交换格式，部署层后端可替换
（`onnx_cpu` / `rknn` / `allwinner`）。

### 8. 算法清单方法论
特征与检测算子大量迁移自**三菱 e-F@ctory FB 库**与**西门子 LGF / SIPLUS CMS 算法清单**
（DKW 自适应基线、Bands 频段能量、MonAnL 迟滞防抖、包络解调等），在电流域落地。

## 算法栈分层架构

```
┌────────────────────────────────────────────────────────────┐
│  00 数据生成与仿真 (00_数据生成与仿真)                        │
│  三相电流仿真器 + 8 类故障注入（管线自检 / ML 打底）           │
├────────────────────────────────────────────────────────────┤
│  Layer 1: 信号预处理 (01_信号预处理)                          │
│  去直流 / 带通(VFD友好) / 归一化 / 三相(N,C) / 流式处理        │
├────────────────────────────────────────────────────────────┤
│  Layer 2: 特征提取 (02_特征提取)                             │
│  快路径(时域/包络) · 慢路径(频域/MCSA/三相) · 统计            │
├────────────────────────────────────────────────────────────┤
│  Layer 3: 检测模型 (03_检测模型)                             │
│  过程状态(规则基线) / 异常检测(AE) / 电能质量                  │
├────────────────────────────────────────────────────────────┤
│  Layer 4: 后处理与决策 (04_后处理与决策)                      │
│  迟滞确认 / 多级报警 / 多模型融合 / 事件聚合                  │
├────────────────────────────────────────────────────────────┤
│  Layer 5: 模型部署 (05_模型导出与部署)                        │
│  PyTorch→ONNX→RKNN / ONNX-CPU / Allwinner · 后端抽象         │
└────────────────────────────────────────────────────────────┘
```
